# wavelength feature preservation ledger

This is the persistent behavioral inventory, established on **2026-11-03**.
It is a preservation contract, not a wishlist or a claim that every feature was
retested today. Architectural replacements must preserve these behaviors or
explicitly document an approved change. Do not delete IDs when retiring features.

The [complete implementation surface](reference/feature-surface.md) inventories
public and private code, operators, panels, settings, shortcuts, hooks, assets,
native patches and tests. The adjacent JSON fingerprints implementation bodies
and declarations. The [change record](developer/feature-changes.md) retains
accepted changes. Source presence and test presence do **not** establish working
registration, correct behavior, installation parity, or successful tests.

## Maintenance contract

1. Before changing a subsystem, find its feature rows and regression checks here.
   Include adjacent systems: selection, undo, transforms, units, serialization,
   asset ownership, visibility, background workers and export inclusion.
2. For every feature change or bug fix, update the affected row, its limitations,
   guide and meaningful verification. Add a stable ID for genuinely new behavior.
3. For a rewrite, compare old/new behavior explicitly. Moving an operator or
   replacing a backend does not authorize removing its UI, shortcuts or semantics.
4. Keep removed/replaced IDs with a **Retired/replaced** status, reason, successor
   and migration instructions. Do not silently reclassify working functionality
   as a stub. Product behavior changes require explicit scope/authorization.
5. Run relevant existing regressions. Add a behavioral regression when needed;
   a symbol/AST snapshot is not a substitute. Distinguish implemented, tested,
   installed and runtime-verified states in the task report.
6. After review, accept the surface change explicitly:
   `python tools/feature_inventory.py --update --feature WL-... --reason "what changed, what was preserved, verification and limits"`.
   Run `python tools/feature_inventory.py` and the normal documentation checks.
   Never regenerate the baseline merely to hide a failing preservation check.

Paths below use `source/` for `addon/wavelength/source/`; `tests/`, `native/`
and `tools/` are checkout-relative. Regression columns identify checks to run,
not an assertion that they currently pass. **Implemented** means code exists;
**Limited/experimental** and **Stub/planned** describe intentional boundaries.

## Deliberate boundaries

- No universal Source 2 model/animation conversion, entity-I/O cross-compiler or
  every-engine level conversion is currently claimed. Preserve explicit stubs.
- A successful world/VIS/entity compile does not prove gameplay, lighting,
  runtime occlusion correctness or every material shader works.
- Blender capabilities available to users (Geometry Nodes, image displacement,
  native mesh editing) are not automatically wavelength-supported engine formats.
- Existing diagnostic experiments, user skin files and one-off map repairs are
  not standalone wavelength product features merely because an agent performed them.
- Architectural cleanup must keep the preservation checks meaningful. If a
  feature is known broken, record that fact and its regression instead of deleting
  its intended behavior from the ledger.
